# Module: Mutator

**AFL++ analog:** Mutation stages — deterministic, splice, havoc

The mutator takes a molecule SMILES and produces a list of chemically valid mutants. It implements three stages of increasing randomness, directly mirroring AFL++'s stage progression. Each returned mutant carries metadata about which stage and operation produced it, for downstream analysis of which mutations are scientifically productive.

---

## Boundary

**Does:**
- Apply chemical graph mutations to produce novel molecules
- Filter all output through the drug-likeness gate before returning
- Tag each mutant with its stage and mutation type
- Accept a mutation budget (n) and return up to n valid mutants

**Does not:**
- Prepare molecules for docking (Prep module)
- Validate dockability (Prep module)
- Apply coverage-based feedback to choose mutations — that is the corpus/power schedule's job
- Know anything about targets, pockets, or affinities

---

## Output Type

```
MutationCandidate:
  smiles: str           # canonical SMILES, passes drug-likeness filter
  stage: str            # "deterministic" | "splice" | "havoc"
  mutation_type: str    # specific operation name (see below)
  parent_smiles: str    # the input SMILES this was derived from
```

The mutator returns a list of `MutationCandidate`. The caller decides how many to use; the mutator produces up to `n` valid, distinct candidates.

---

## Stage 1: Deterministic

Systematic, exhaustive mutations at every valid position. Analogous to AFL++'s bit-flip and arithmetic deterministic stages — slow but complete. Every mutable site is visited.

A corpus entry goes through the deterministic stage on its first selection only,
then is promoted. This mirrors AFL++'s `SKIP_TO_HAVOC` flag: the systematic work
has been done, so later selections spend their budget stochastically.

The promotion rule is in `biofuzz/corpus/scheduler.py::select_stage`, and the
trap it avoids is worth naming. "Splice if a donor exists, else havoc" makes
havoc unreachable, because a donor exists whenever the corpus holds more than one
molecule. Splice is therefore gated behind a probability (25%) and havoc is the
default.

Operations:

**`atom_scan`**
For each atom: try every valid substitution (C→N, C→O, N→C, S→O, ring C→N).
One candidate per (atom_index, target_element) pair. This is systematic bit-flip equivalent.

**`substituent_scan`**
For each open aromatic position: try attaching each group in the substituent library: `–F`, `–Cl`, `–Br`, `–CH3`, `–OH`, `–NH2`, `–CN`, `–CF3`, `–OCH3`, `–COOH`.
One candidate per (position, group) pair.

**`halogen_scan`**
For each non-halogenated aromatic position: try F, Cl, Br. For each existing halogen: try all other halogens. Halogens are important for potency and metabolic stability — worth a dedicated pass.

---

## Stage 2: Splice

Structural crossover between two corpus entries. The direct analog of AFL++'s splice stage, which combines the first half of one input with the second half of another.

For molecules, "splicing" means combining the Murcko scaffold of one molecule with the R-groups of another, or swapping functional group attachments between two molecules that share a substructure.

Operations:

**`scaffold_splice`**
Decompose both molecules into Murcko scaffold + R-groups using RDKit's `MurckoDecompose`.
Attach the R-groups from molecule B to the scaffold of molecule A (and vice versa).
Requires: access to a second `CorpusEntry` (the "donor"). The fuzzer supplies the donor by sampling another corpus entry with high coverage signal.

**`fragment_graft`**
Identify a shared SMARTS substructure between two molecules. Swap the non-shared portions. This is more flexible than Murcko decomposition for molecules with unusual scaffolds.

The splice stage requires a donor molecule argument. The mutator API accepts an optional `donor_smiles` parameter; if omitted, splice operations are skipped.

---

## Stage 3: Havoc

Stochastic multi-operation mutations. Multiple operations are combined randomly in a single pass. This is where structurally novel molecules emerge.

Operations (any subset may be combined):

**`atom_type_swap`** — random atom substitution at one position  
**`add_substituent`** — attach a randomly chosen group to a random aromatic position  
**`remove_substituent`** — remove a non-ring terminal substituent  
**`linker_extend`** — insert one CH2 into a chain between two non-ring atoms  
**`linker_contract`** — remove one CH2 from a chain  
**`ring_atom_swap`** — change one ring carbon to nitrogen (pyridine-ification)  
**`bioisostere_replace`** — replace a functional group with a known bioisostere (see below)  
**`ring_open`** — break one ring bond to form an open chain  
**`ring_close`** — cyclize a chain with a new bond (only if valence permits and ring size 5–6)

Havoc applies 1–8 operations per molecule in sequence, randomly selected, then validates the result. Multiple havoc candidates are generated by repeating this process with different random seeds.

---

## Bioisostere Library

`bioisostere_replace` uses a hardcoded SMARTS→SMARTS mapping of classical bioisostere pairs. The library is defined in the mutator module and can be extended without changing any other module.

The implemented set (`biofuzz/mutator/library.py`) is a **representative
subset**, not a complete bioisostere table:

- `–COOH` → tetrazole
- `–OH` → `–F`, `–NH2`
- `–CH2–` (linker) → `–O–`, `–NH–`

Pairs worth adding, and deliberately not yet implemented:

- `–COOH` → hydroxamic acid, sulfonamide, phosphonic acid
- `–CONH–` → reverse amide, urea, carbamate, sulfonamide
- ester → ketone, thioester, amide

phenyl → pyridine is already covered in practice by the `ring_atom_swap`
havoc operation, so it is not duplicated here. The library is a flat list of
(SMARTS, replacement) pairs and extending it touches no other module.

## Validity Gate

All candidates pass through the drug-likeness filter before being returned. The filter parameters are passed in by the caller (from config) — the mutator does not hardcode thresholds.

Filter checks:
- MW in [min_mw, max_mw]
- logP ≤ max_logp
- HBD ≤ max_hbd
- HBA ≤ max_hba
- Rotatable bonds ≤ max_rot_bonds
- Connected graph (no disconnected fragments)
- RDKit `SanitizeMol` passes
- **No unstable motif** (`check_stability=True`, see `mutator/alerts.py`)

Failed candidates are discarded. The mutator keeps attempting until it fills the budget or exhausts `max_attempts = max(50, n * 20)`.

### Chemical plausibility is not a property bound

Property bounds say nothing about whether a molecule can exist. `atom_scan`
walking an ethoxy tail one atom at a time produces `-O-N(H)-O-` and `-O-CH2-O-H`
— a hydroxylamine ether and a hemiacetal — which pass every check above, dock
well, and would be saved as findings. `mutator/alerts.py` is the gate for this.

The catalog is deliberately **narrow**: it targets motifs that are unstable or
not isolable (acyclic peroxides, N–O single bonds, acetals and aminals on acyclic
carbons, geminal diols, acyl and heteroatom halides, allenes), not motifs that
are merely unattractive. Ring-membership and acylation exclusions are what make
that distinction hold, so that artemisinin's endoperoxide, paroxetine's
benzodioxole, aspirin's phenol ester and vorinostat's hydroxamic acid all pass.
`tests/test_alerts.py` asserts 0 of the 250 approved-drug seeds are flagged.

RDKit's BRENK catalog was tried and rejected for the in-loop gate: it flags
aspirin and every aniline, both well represented among approved drugs. PAINS and
BRENK run in triage instead, where a flag is advisory rather than a hard reject.

### Bounds are per-target, and they must admit the target's chemical class

Filter parameters come from the caller (`molecules:` in config, overlaid
per-target). **Set them from the chemical class that binds the target.** A global
550 Da / logP 5.0 envelope rejects peptidomimetic protease inhibitors (600–720
Da) and lipophilic type-II kinase inhibitors (logP > 5) — whole classes — at the
preparation step, silently, before docking. Two of the five bundled targets need
an override for exactly this reason.

This is a chemical-space bound, not a known-inhibitor dependency: nothing is
seeded or scored against a specific drug. Ligand efficiency, not a blanket MW
cap, is the instrument for keeping size honest, because it asks what the extra
atoms buy. Where a target ships a validation reference drug,
`tests/test_calibration.py` checks the target's own bounds can at least prepare
it. See [adding_targets.md](../adding_targets.md).

## Stage Selection

The fuzzer tracks the stage each entry is at, via `CorpusEntry.times_selected`
rather than a stored stage field. First selection is deterministic; afterwards,
havoc, with splice mixed in at 25% when a donor exists.

Donor selection is **uniform random** over the rest of the corpus. Weighting it
by coverage signal, as `corpus.md` suggests, is unimplemented.

`CorpusEntry.mutation_lineage` records the last 10 operation names that produced
an entry, so a completed campaign can be analysed for which operations actually
yield coverage.

---

## Verification

`tests/test_mutator.py` runs each stage against phenol — deterministic and havoc
directly, splice with a real donor — and asserts every returned candidate is
valid, distinct from its parent, and inside the filter bounds.

`tests/test_alerts.py` pins the structural-alert catalog in both directions: the
two motifs the deterministic stage really does generate are rejected, and none of
the 250 approved-drug seeds is. That second assertion is the important one; it is
what stops the catalog being tightened into something that would reject real
drugs.

`tests/test_scheduler.py` covers stage selection, including that havoc is
reachable and dominant after the first selection.
