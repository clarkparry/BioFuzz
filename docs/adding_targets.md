# Adding a New Target

A target is a directory `targets/<name>/` containing a prepared receptor, a
docking box, and a pocket residue set. All of it — except picking the source
structure — is generated by `.agent/tools/prepare_target_fixture.py`.

## 1. Find a source structure

Search [RCSB PDB](https://www.rcsb.org) for your protein. You need a
**co-crystal structure**: the box and pocket are derived directly from the
coordinates of a bound ligand, not from a pocket-detection algorithm, so a
ligand-free (apo) structure won't work.

Checklist when picking a PDB entry:

- **A real, known inhibitor is bound in the site you care about.** The
  ligand's PDB chemical-component ID (three/five-letter code, e.g. `MK1`)
  drives everything downstream — look it up on the entry's "Ligands" tab.
- **Wild-type, unless you specifically want a mutant/resistance study.**
  Many high-resolution, recently-deposited structures for well-studied drugs
  turn out to be mutant complexes — check the title and the polymer entity's
  mutation annotation, don't assume from resolution/date alone.
- **Resolution ≲ 2.5 Å.** Below ~2 Å is good; above ~3 Å, side-chain and
  ligand geometry gets unreliable.
- **Check whether the active site needs more than one chain.** Most targets
  are fine with a single chain. Obligate dimers whose site sits at the chain
  interface (e.g. HIV-1 protease) need both chains, or the pocket residue
  list will be missing half its contacts.
- Cross-check candidates: RCSB's ligand search
  (`rcsb_nonpolymer_instance_annotation.comp_id`) lists every entry
  containing a given ligand code, sortable by resolution — use it to compare
  options for the same compound rather than trusting the first hit.

## 2. Add a `TargetSpec`

In `.agent/tools/prepare_target_fixture.py`, add an entry to `TARGET_SPECS`:

```python
"my_target": TargetSpec(
    name="my_target",
    pdb_id="1ABC",              # RCSB entry ID
    protein_chains=("A",),      # add more chains only if the site spans them
    ligand_code="XYZ",          # the bound ligand's chemical-component ID
    inhibitor_name="my_drug",   # used for reference_ligands/<name>.smi/.pdbqt
),
```

## 3. Run it

```sh
python .agent/tools/prepare_target_fixture.py my_target
```

This downloads the structure and the ligand's chemical-component definition
from RCSB, then automatically:

- isolates the named chain(s), strips waters/hydrogens/other heteroatoms
- computes the docking box from the bound ligand's coordinates (center =
  bounding-box midpoint, size = extent + 8 Å padding, clamped to 18–28 Å)
- computes the pocket residue set (any receptor residue within 4.5 Å of the
  ligand)
- converts the receptor to PDBQT via Meeko's `mk_prepare_receptor.py`
- runs the bound ligand's SMILES through the same prep pipeline used at
  fuzzing time to produce a reference ligand PDBQT

Output: `targets/my_target/protein.pdbqt`, `targets/my_target/config.yaml`
(box + pocket only), and `targets/my_target/reference_ligands/`.

## 4. Calibrate the oracle threshold (manual)

The script has no way to know a realistic binding affinity for the target —
that requires actually docking the reference ligand. Run it through
`biofuzz-fuzz` (or dock it directly) and add an `oracle:` block to the
generated `config.yaml` by hand, e.g.:

```yaml
# Reference: my_drug, ~-9.1 kcal/mol
oracle:
  affinity_threshold: -8.5
  strain_threshold: 3.5
```

Without this, the target falls back to the global defaults in the
repo-level `config.yaml`.

## Known limitation

Box/pocket placement is only as good as the source structure: it assumes
the crystallographic ligand pose accurately marks the site you want, and
that a flat distance cutoff is a reasonable proxy for "active site." That
holds for a rigid small-molecule pocket but can undershoot something with
a flexible element (e.g. HIV-1 protease's flaps) — `targets/hiv_protease/`
is hand-curated for exactly this reason rather than using the script's
output verbatim.
