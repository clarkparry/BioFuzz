Task: Hashed fingerprint bitmap coverage
Date: 2026-04-13

Objective
- Replace union-only novelty guidance with the hashed fingerprint bitmap coverage model from `COVERAGE.md`.
- Preserve union residue coverage as the human-readable progress metric.
- Persist enough coverage state to resume campaigns without losing epoch-window novelty memory.

Challenges
- Keep the existing `coverage_ratio`/`new_bits` compatibility surface intact while shifting scheduling to hashed novelty.
- Support resume from both the old union-only checkpoint format and the new bitmap checkpoint format.
- Add config validation without breaking existing tests that monkeypatch partial global config dictionaries.

Approach
1) Rebuilt `biofuzz/core/coverage.py` around a `CoverageObservation` model with:
   - stable residue-to-bit mapping,
   - exact integer fingerprint masks,
   - deterministic hashed bitmap indexing,
   - current/previous epoch maps with rotation,
   - persisted novelty counters and union coverage.
2) Added coverage config defaults and validation in `biofuzz/docking/config.py`, then wired the normalized coverage config through `main.py` into `biofuzz/core/fuzzer.py`.
3) Switched corpus scoring/power scheduling to use hashed `novelty_score` as the primary coverage signal while retaining legacy `new_bits` on corpus entries for compatibility/reporting.
4) Updated seed triage and mutation processing to consume `CoverageMap.observe(...)` so hashed novelty affects both initial corpus bootstrap and ongoing scheduling.
5) Added regression coverage for:
   - deterministic mapping/hash behavior,
   - strong/weak/none novelty classification,
   - epoch rotation,
   - legacy + new checkpoint loading,
   - config validation,
   - scheduler use of hashed novelty,
   - run stats/reporting of bitmap metrics.

Validation
- `./.venv/bin/python -m pytest -q tests/test_coverage.py tests/test_config.py tests/test_corpus.py tests/test_fuzzer.py` -> `56 passed`
- `./.venv/bin/python -m pytest -q` -> `110 passed`
