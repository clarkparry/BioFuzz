Task: Align BioFuzz runtime behavior with `BIOFUZZ_STRUCTURE.md` after implementation audit.

Goals:
- Make `config.yaml` act as a real global default layer for target oracle settings.
- Match the documented runtime semantics for heavy-atom coverage and confirmed-hit saving.
- Harden selectivity/oracle behavior so transient docking failures do not become false negatives.

Challenges:
- The existing repository already matched the high-level module structure, so the remaining gaps were semantic rather than architectural.
- `TargetConfig` is a fully materialized dataclass, which means global-vs-target precedence can only be inferred heuristically once defaults are populated.
- Confirmation docking and selectivity logic both touch the core loop, so the patch needed targeted regression tests to avoid destabilizing the fuzzer.

Approach:
1. Audited the runtime against the spec and identified four concrete drifts:
   - `config.yaml` oracle defaults were loaded but not applied to targets.
   - Coverage fingerprints counted hydrogen contacts instead of heavy atoms only.
   - Fast fuzzing hits were written directly to findings without a confirmation re-dock.
   - Selectivity checks re-prepared ligands with default settings and treated docking failures as hard failures.
2. Patched the implementation:
   - Added target/global oracle default merging and wired it into `main.py`.
   - Filtered hydrogen atoms out of pocket coverage fingerprints.
   - Added confirmation docking before saving findings, using `exhaustiveness_confirm`.
   - Passed prepared ligand/config context into selectivity checks and changed unavailable selectivity runs to report as skipped instead of failed.
   - Made findings IDs use nanosecond timestamps to avoid same-second overwrite collisions.
3. Added regression tests covering config layering, heavy-atom coverage, selectivity context propagation/skip semantics, and hit confirmation before save.
4. Re-ran the full test suite and CLI smoke path.

Validation:
- `pytest -q` => `32 passed, 8 skipped`.
- `python3 main.py --target hiv_protease --max-iterations 0 --workers 1 --output runs/smoke_cli_2026_03_29_spec_alignment_final` => successful completion.

Outcome:
- BioFuzz now more closely matches the intended 10-phase design at runtime, not just structurally, while remaining green in the current dependency-limited workspace.
