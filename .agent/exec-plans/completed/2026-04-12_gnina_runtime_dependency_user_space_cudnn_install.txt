Task: make GNINA runnable on this host without root package installs

Problem
- GNINA binary was present but failed at process start due missing runtime libs (`libcudnn.so.9` plus CUDA 12 math/runtime libs).
- Host shell did not permit passwordless sudo, so system-level apt installation was not available within this session.

Approach
- Installed user-space CUDA/cuDNN runtime wheels into `.venv`:
  - `nvidia-cudnn-cu12`
  - `nvidia-cuda-runtime-cu12`
  - `nvidia-cublas-cu12`
  - `nvidia-cusolver-cu12`
  - `nvidia-cusparse-cu12`
  - `nvidia-cufft-cu12`
- Wrapped `.agent/tools/bin/gnina` with a shell launcher that exports `LD_LIBRARY_PATH` to `.venv` NVIDIA library directories and execs the original binary (`gnina.bin`).
- Verified `gnina --help` executes successfully after wrapper setup.

Additional runtime fix
- GNINA docking logs use a mode-table format not previously parsed by `parse_log` (5 numeric columns vs Vina's 4-column format).
- Updated `biofuzz/docking/parser.py` to parse both Vina and GNINA mode lines.
- Added regression coverage in `tests/test_parser.py` for GNINA table parsing.

Validation
- `gnina --help` succeeds.
- Live GNINA dock call returns success and parsed modes.
- Full test suite passes (`82 passed`).
- CLI smoke with `--engine gnina` now completes and reports non-zero coverage/corpus growth.
