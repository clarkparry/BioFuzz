Task: Make user-abort (`Ctrl-C`) behavior during seed docking match the same graceful shutdown path used during normal fuzzing.

Challenges:
- Seed docking ran before the main loop's KeyboardInterrupt/cleanup path, causing inconsistent abort handling.
- Existing seed bootstrap used an early return for empty corpus, bypassing the unified stop/finalization flow.

Approach:
- Move seed-stage stop bookkeeping onto the same `stopped_reason` state machine used by the regular fuzzing loop.
- Catch `KeyboardInterrupt` during seed docking and mark the run as manual abort (`keyboard_interrupt`) without continuing to additional seeds.
- Replace seed empty-corpus early return with `stopped_reason = "empty_corpus"` so final checkpoint/summary handling remains unified.
- Add regression coverage for keyboard interrupt during seed docking.

Completed Approach:
- Updated `biofuzz/core/fuzzer.py` so seed-stage interrupts set `stopped_reason="keyboard_interrupt"`, trigger the same shutdown/checkpoint path, and avoid further seed processing.
- Changed seed-stage empty corpus handling to use the run status flow rather than returning before finalization.
- Added `test_run_handles_keyboard_interrupt_during_seed_docking` to verify stop reason, single dock attempt, and checkpoint persistence.

Outcome:
- Aborting during seed docking now behaves like aborting during regular fuzzing, including graceful summary-producing run completion semantics.
