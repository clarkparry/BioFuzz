Task: Iteration-cap cleanup hardening after AGENTS-guided build verification.

Goals:
- Prevent temporary pose file leakage when `max_iterations` is reached mid docking batch.
- Preserve existing fuzz-loop behavior and checkpoint semantics.
- Lock the behavior with a regression test.

Challenges:
- `run()` batches docking results before per-result processing; early exits can leave generated pose files unprocessed.
- Cleanup must apply to both processed and skipped results without changing hit/coverage logic.

Approach:
1) Audited `core/fuzzer.py` around the result-processing loop and identified early-break temp-file leak risk.
2) Added `_cleanup_pose_path()` helper and adjusted loop control to:
   - clean all unprocessed result pose files once iteration cap is reached,
   - defer outer-loop break until the batch has been cleanup-scanned.
3) Added regression test `test_run_cleans_unprocessed_pose_files_when_max_iterations_hit` in `tests/test_fuzzer.py`.
4) Re-ran tests and CLI smoke validation.

Validation:
- `pytest -q` => `27 passed, 5 skipped`.
- `python3 main.py --target hiv_protease --max-iterations 0 --workers 1 --output runs/smoke_cli_after_cleanup` => successful completion.

Outcome:
- BioFuzz now guarantees pose temp-file cleanup for both processed and skipped results under iteration-capped runs.
