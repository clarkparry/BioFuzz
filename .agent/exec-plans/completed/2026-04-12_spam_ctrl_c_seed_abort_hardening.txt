Task: Harden manual-abort behavior so spammed `Ctrl-C` during seed docking aborts immediately and still reaches the same graceful summary/checkpoint path as regular fuzzing.

Challenges:
- During seed docking, repeated `Ctrl-C` could kill the docking child process without reliably raising a parent-side interrupt on every keypress, making the run appear to skip to later seeds before eventually stopping.
- Additional `Ctrl-C` events after first abort request could race before SIGINT suppression was enabled, risking inconsistent shutdown behavior.

Approach:
- Teach docking runner to treat SIGINT process exits as true user interrupts (`KeyboardInterrupt`) instead of generic docking failures.
- Enable SIGINT suppression immediately upon first manual-abort capture so repeated `Ctrl-C` does not disrupt checkpoint/final-summary flow.
- Keep run teardown/reporting path unchanged so CLI still prints stopped summary and returns interrupt exit status.

Completed Approach:
- Updated `biofuzz/docking/runner.py` to raise `KeyboardInterrupt` when docking subprocess exits via SIGINT return codes (`-2`/`130`).
- Updated `biofuzz/core/fuzzer.py` to suppress SIGINT immediately when manual abort is detected (seed stage or main fuzzing loop), then restore original handler after finalization.
- Added runner regression coverage for SIGINT exit mapping to `KeyboardInterrupt`.

Outcome:
- Spammed `Ctrl-C` during seed mode now aborts like regular fuzzing: stop request is honored once, remaining interrupts are ignored during teardown, and summary/checkpoint flow completes consistently.
- Verification status: `pytest -q` -> `60 passed, 11 skipped`.
