Task: Align BioFuzz implementation with BIOFUZZ_STRUCTURE config semantics and harden runtime behavior

Challenges:
- Existing implementation was functionally complete but did not wire corpus weighting/max-size knobs from `config.yaml` into the active fuzzer loop.
- Corpus behavior (priority, persistence, bounded size) lacked explicit phase-level tests.
- Docking engine selection was brittle when `gnina` was configured but only `vina`-family binaries were installed.

Approach:
1. Extended `biofuzz/core/corpus.py` with optional `max_size` enforcement and persisted `max_size` in save/load payloads.
2. Added weighted priority computation in `biofuzz/core/fuzzer.py` and passed corpus weight parameters through `run()`.
3. Wired global corpus config fields in `main.py` into the fuzzer invocation.
4. Hardened `biofuzz/docking/runner.py` binary resolution to fallback from requested engine to other supported binaries.
5. Added new tests:
   - `tests/test_corpus.py` for queue ordering, persistence, max-size trimming, and weighted priority math.
   - `tests/test_runner.py` for binary resolution fallback behavior.
6. Re-ran test suite and CLI smoke run.

Successful completion:
- `pytest -q` => `16 passed, 4 skipped`.
- `python3 main.py --target hiv_protease --max-iterations 0 --workers 1 --output runs/smoke_cli` executes successfully.
